# aigc-lite v0.6.0 release closure

**Status:** verified release baseline

**Date:** 2026-09-30

**Package version:** `0.6.0`

**Git anchor:** annotated tag `v0.6.0`

This release freezes the first **Authority Separation Baseline** before real
RIME cases, Lean companion workflows, and hostile research Agents begin
attacking the protocol.

## Release scope

- separate orthogonal kernel verification from epistemic independence;
- make QualificationReceipt historical and require an explicit immutable
  KnowledgeAdmissionReceipt before entering the current knowledge view;
- enforce the admission/current-binding relationship in both SQLite and
  PostgreSQL;
- add a vendor-neutral external Enforcer Adapter, host-owned Ed25519 trust
  roots, strict signed receipt verification, persistent indeterminate dispatch
  state, and fail-closed reconciliation;
- retain `auto_promote` only as a compatibility request for a proposal-only
  workflow Gate evaluation. Agent execution cannot apply `promotion_stage`;
- publish the normative authority transition matrix and the first adversarial
  silent-promotion regression suite;
- make `/mcp/` canonical while accepting exact `/mcp` without an HTTP redirect,
  preserving POST compatibility with the default non-following SDK client;
- freeze the future Controlled Patch Runner security contract without adding a
  source-mutation API or granting failed Runs any write authority;
- reorganize `DESIGN.md` into current architecture, known gaps, and historical
  roadmap so old plans are not mistaken for runtime truth.

## Authority non-claims

The following distinctions are release invariants:

```text
candidate storage
  != workflow stage
  != qualification
  != knowledge admission
  != current use
  != execution authorization
```

A passing Agent VerificationAttempt can produce evidence and a proposal-only
workflow evaluation. It cannot issue a QualificationReceipt, create a
KnowledgeAdmissionReceipt, select a CurrentUseBinding, mint an
AuthorizationGrant, apply a runtime policy, or assert verifier independence.

Signed Enforcement Receipts authenticate a payload from a configured key. They
do not prove that the external signer is truthful, independently administered,
hardware-attested, or able to stop an indeterminate workload.

## Migration note

Alembic head is `0020_knowledge_admission`. Upgrading:

- adds external enforcer signature and dispatch persistence in revisions
  `0018` and `0019`;
- adds immutable KnowledgeAdmissionReceipt records in revision `0020`;
- marks legacy current knowledge bindings stale until an explicit admission is
  issued;
- leaves historical QualificationReceipts and evidence intact.

No migration is required for the `auto_promote` hardening. Existing plans with
the stored value `true` now receive proposal-only evaluation semantics.
