# aigc-lite v0.3.0 release acceptance

**Status:** locally frozen source baseline

**Date:** 2026-09-28

**Release kind:** execution-memory and verifiable-research milestone

**Git anchor:** annotated tag `v0.3.0`

This record defines the source and validation boundary of `v0.3.0`. The tag
anchors committed source; it does not claim a container registry digest, PyPI
publication, hosted deployment, or independent security/scientific review.

## Release identity

Version-bearing surfaces are aligned at `0.3.0`:

- Python package metadata and `app.__version__`;
- FastAPI and MCP server metadata;
- frontend package and lock file.

Generated frontend bundles, wheels, databases, local `.env` files, caches,
logs, IDE state, credentials, and runtime evidence are excluded from the tag.

## Included milestone

Relative to `v0.2.0`, this release adds:

- encrypted workspace Credential Store references;
- Agent turn/tool/wall-clock budgets, cancellation propagation, and local tool
  execution backends;
- persistent time-wheel-backed schedules and explicit `TaskRunner` targets;
- Run-linked Artifact/Citation records and SQLite FTS5 unified search;
- Run Explorer and unified search UI;
- Protocol/Claim/Receipt/Review/Freeze evidence primitives and NanoJev Decision
  Lab ingestion;
- Research Registry, typed Claim Relations, Verification Attempts, fail-closed
  Promotion Gates, immutable Verification Plans, and Agent/scheduled
  Verification Runner closure.

The release preserves explicit epistemic boundaries: source closure is not
truth, Agent verification is not independent review, release readiness does
not authorize external action, and private/local configuration is not part of
the public core.

## Validation profile

The accepted candidate must pass from the repository root:

```text
python -m pytest -q
python -m ruff check .
python -m compileall -q app
npm ci                         (frontend/)
npm run build                  (frontend/)
python -m pip_audit --local --skip-editable
npm audit --omit=dev --audit-level=high  (frontend/)
python -m pip wheel . --no-deps --wheel-dir <temporary-directory>
```

The wheel must include Alembic migrations through
`0010_verification_runner`. A clean installation outside the checkout must be
able to initialize a new SQLite database at that revision.

Accepted local results on 2026-09-28:

- backend: 123 tests passed; Ruff and byte-compilation passed;
- frontend: clean `npm ci` and production build passed;
- dependency audit: npm reported 0 vulnerabilities and pip-audit reported no
  known vulnerabilities;
- public-tree scan: no credential-shaped value, private key, local proxy,
  company GitLab host, database, or non-example `.env` file was selected;
- wheel smoke: `aigc_lite-0.3.0-py3-none-any.whl` built successfully, contained
  11 migration modules including `0010_verification_runner`, installed outside
  the checkout, reported package version `0.3.0`, and initialized a fresh
  SQLite database at revision `0010_verification_runner`.

## Known boundaries

- SQLite remains a single-process quick-start backend; PostgreSQL has matching
  repository methods but no live database contract job in CI.
- Schedule delivery is at-least-once around process interruption and does not
  provide distributed leasing across multiple application instances.
- Thread-backed synchronous tools cannot be force-terminated; process mode is
  required for hard cancellation.
- URL validation and deployment hardening remain operator responsibilities;
  authenticated polling should be wrapped as a scoped tool rather than adding
  credentials to generic HTTP poll payloads.
- Verification result contracts and promotion records establish traceability,
  not scientific truth or organizational authorization.
