# aigc-lite v0.7.0 candidate validation

**Status:** local release checks passed; GitHub CI pending; untagged and unpublished

**Date:** 2026-10-14

**Validated code commit:** `698a679dd12dcacabb1f4c5c601e7102d8f81948`

This is a candidate acceptance record, **not** a `v0.7.0` release closure.
The validated code includes the merged `be13369` authority branch, the
integer-timeout handoff fix, and the `0.7.0` package metadata. This document
was committed afterward; its own commit is not the wheel source identity.
No package was published and no tag was created.

## Scope and compatibility

- Core and ROS 2 bridge wheel versions are `0.7.0`.
- The optional `aigc-lite-mde-casepack` remains at `0.1.0`, candidate-only,
  with an exact `aigc-lite==0.7.0` dependency. Released `v0.6.0` lacks the
  Bio/Citation v1 helpers it imports. Compatibility with later core versions
  is not inferred from the version number and requires a separate review.
- The MDE casepack is not included in the core wheel and is not automatically
  discovered. Its diagnostics have no HTTP/MCP authority-writing route.
- The authorization invocation digest now normalizes an integer tool timeout
  such as `30` to the same representation as `30.0` before both Grant
  consumption and external dispatch. The regression covers the one-time
  consumed-Grant handoff, not merely fact serialization.

## Unverified and non-claims

- GitHub CI for the documentation commit and the pushed branch has not yet
  completed at the time this candidate record was written. A tag or published
  release requires checking the final commit and recording CI separately.
- Math Project 003 still has no passing full Comparator/kernel replay.
  Neither the Fibre Criterion case nor a paper review of a different theorem
  supplies that missing result.
- Bio/Citation MDE reports are conditional, candidate-only diagnostics. A
  signature and key fingerprint bind claimed records to configured keys; they
  do not prove that the real-world sample or data provenance was truthful.
  No Disambiguation Certificate, QualificationReceipt, CurrentUseBinding, or
  AuthorizationGrant is produced by the casepack.
- Docker startup checks do not establish a complete OS sandbox. ROS 2
  simulator evaluation is not real hardware acceptance. Same-checker
  cross-host replay is not independent mathematical verification.

The next release decision should use the exact source commit, this local
evidence, GitHub CI results, and any remaining external acceptance as
separate inputs. Do not convert this candidate note into a release claim by
renaming it or adding a tag alone.
