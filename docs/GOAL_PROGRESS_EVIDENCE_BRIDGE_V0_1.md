# Goal Progress Evidence Bridge v0.1

This is a fail-closed revision of the read-only [v0 diagnostic](GOAL_PROGRESS_EVIDENCE_BRIDGE_V0.md), not a new qualification or execution gate. The frozen Goal criterion keeps `goal.current_knowledge_qualification.v0` and its four-field shape, so an existing native Goal can be evaluated without changing its historical identity. Each new response identifies **`GoalProgressEvidenceBridge.v0.1`**, its new host-rule hash, implementation source hashes, and the database snapshot. Saved v0 responses remain historical records and are not reinterpreted as v0.1.

For `math.formal.v1` and `math.formal.project.v2`, the evaluator now applies the same frozen-proof Attempt eligibility and selection projection as the authoritative qualification chain **on every assessment**, not only when a proof invalidation exists. An `ADMITTED` historical math receipt with no reconstructible eligible selected Attempt returns `UNRESOLVED`; it cannot obtain `SUPPORTED_AS_OF_SNAPSHOT` merely because no invalidation decision matches an empty set. If the selected or historically possible Attempt set intersects formally invalidated Attempts, the result is `BLOCKED`. A historical ambiguous set is conservative: its members are possible selections, not evidence that all were actually used. For non-math profiles, the existing profile-specific qualification checks remain in force; the math projection is not a universal evidence rule.

The service still reads one bounded, read-only database snapshot. It does not update `CurrentUseBinding`, create a `QualificationReceipt` or `AuthorizationGrant`, or permit a later action. The diagnosis is conditional on the frozen database records, registered Profile and policy, and installed source bytes; it does not independently rerun a kernel, authenticate real-world sources, or prove the scientific claim. Any future tool dispatch must recheck the authoritative current-use and Grant paths at invocation time.

The synthetic zero-selection regression demonstrates fail-closed behavior for a malformed or unreconstructable historical shape. It is not evidence that the published v0.7.0 runtime issued a legitimate Receipt of that shape. The versioned diagnostic correction is an acceptance check for the next candidate, not a retroactive change to the v0.7.0 release or to its historical test results.
